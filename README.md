# Чайный движ: мониторинг каталога chazhijitea.com

Бот следит за чаями на [chazhijitea.com](https://chazhijitea.com/) и пишет в Telegram-чат **«Чайный движ»**, когда:

| | Событие | Пример |
|---|---|---|
| 🆕 | **Новый товар** (или новый вариант у существующего, например другой год) | `Box (75g) · 48.00 MYR · 2 шт.` |
| ✅ | **Снова в наличии**: было «Out of stock», стало «в наличии» | `Whole Cake (357g): 4 шт. · 72.00 MYR` |
| 📦 | **Изменилось количество**, указанное на сайте | `📉 Box (100g): 9 шт. → 7 шт. (−2)` |

В разделе 📦 также видно, когда позиция закончилась (`❌ 2 шт. → нет в наличии`) или пропала с сайта (`🚫`).

Следим **только за полной упаковкой**. Пробники в карточке товара (`Pocket-sized (10g)`, `Pocket-sized (8g)`, `Single Ball` и т. п.) не отслеживаются.

## Как это работает

* По расписанию GitHub Actions запускает `python -m tea_monitor` (файл `.github/workflows/monitor.yml`). В расписании стоит «каждые 10 минут», но GitHub запускает реже: на практике раз в 30–45 минут.
* Список чаёв берётся из коллекции [All Teas](https://chazhijitea.com/collections/all-teas) и всех товаров с типом «Tea» (Shopify `products.json`).
* Количество берётся ровно в том виде, как его показывает сайт на странице товара: «20 in stock», «Low stock: 4 left», «Out of stock».
* Прошлое состояние лежит в `state/state.json`. После каждой проверки, если что-то изменилось, бот коммитит этот файл. История коммитов заодно служит историей остатков.
* Первый запуск только запоминает каталог. Уведомления начинаются со следующей проверки.
* Если Telegram временно недоступен, состояние не сохраняется: те же изменения отправятся при следующей проверке.

### Как отличается пробник от полной упаковки

Вариант считается пробником, если:
1. в его названии есть слово из `sample_keywords` в `config.json` (`Pocket…`, `Sample`, `Single Ball`, `Пробник`…), **или**
2. он весит не больше `sample_max_grams` (30 г), а в той же карточке есть вариант хотя бы вдвое тяжелее.

Сейчас на сайте 66 чаёв: отслеживается 90 позиций полной упаковки, пробники отброшены. Какие позиции сейчас под наблюдением, видно в отчёте каждого запуска (Actions → запуск → Summary).

## Подключение Telegram (один раз, ~3 минуты)

Боты Telegram не умеют сами создавать чаты, поэтому группу создаёте вы. Бот ищет группу «Чайный движ», а если такой нет, подключается к единственной группе, в которую его добавили (название может быть любым).

1. **Создайте бота.** В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя (например, «Чайный движ») и username, оканчивающийся на `bot`. BotFather пришлёт **токен** вида `123456789:AAH…`.
2. **Создайте группу «Чайный движ».** В Telegram: «Новая группа» → добавьте в участники своего бота (поиск по username) → название группы **Чайный движ**.
3. **Отдайте токен GitHub.** Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:
   * Name: `TELEGRAM_BOT_TOKEN`
   * Secret: токен от BotFather.
4. **Запустите проверку.** Вкладка **Actions → «Мониторинг чая» → Run workflow** (можно поставить галочку «тестовое сообщение»). Бот найдёт группу и пришлёт в неё приветствие. Дальше всё работает само.

> Бот узнаёт о группе из события «меня добавили в чат», а Telegram хранит такие события 24 часа. Если между шагами 2 и 4 прошло больше суток, удалите бота из группы и добавьте снова (или напишите в группе `/start@имя_бота`) и запустите проверку ещё раз.

Найденный id чата сохраняется в `state/state.json`. Без токена бота он бесполезен. Если не хотите хранить id в репозитории или хотите писать в другой чат или канал, задайте секрет `TELEGRAM_CHAT_ID`: он важнее поиска по названию. Для канала бот должен быть администратором с правом публикации.

## Настройки — `config.json`

| Параметр | Что значит |
|---|---|
| `shop_url` | адрес магазина (Shopify) |
| `tea_collections` | коллекции, товары из которых считаются чаем |
| `tea_product_types` | типы товаров Shopify, которые считаются чаем |
| `currency` | валюта для сообщений |
| `telegram_chat_title` | название чата, который ищет бот |
| `sample_keywords` | слова-признаки пробника в названии варианта |
| `sample_max_grams` | «малый вес» для пробника, г |
| `request_delay_seconds` | пауза между запросами к сайту, с |

Частота проверок задаётся строкой `cron` в `.github/workflows/monitor.yml`.

## Локальный запуск

```bash
pip install -r requirements.txt
python -m tea_monitor --dry-run --state /tmp/state.json --save   # первый проход: запомнить каталог
python -m tea_monitor --dry-run --state /tmp/state.json          # показать, что ушло бы в Telegram
python -m unittest discover -s tests -t .                        # тесты
```

С переменными окружения `TELEGRAM_BOT_TOKEN` (и при желании `TELEGRAM_CHAT_ID`) и без `--dry-run` сообщения уходят в Telegram.

## Что важно знать

* Расписание GitHub Actions работает только в ветке по умолчанию. GitHub не гарантирует точное время: запуски «каждые 10 минут» на деле идут примерно раз в 30–45 минут.
* Репозиторий публичный, поэтому минуты Actions бесплатны. `state/state.json` и отчёты запусков видны всем, но там только открытые данные каталога.
* Если сайт недоступен, запуск помечается ошибкой (GitHub пришлёт письмо), а состояние не меняется. Если вдруг «пропадёт» больше половины каталога, это считается сбоем сайта, а не изменениями.
